# Text-based video summarization

A 2023 research prototype combining audio extraction, noise reduction, speech recognition, topic tagging and extractive text summarization. It explores LexRank, TextRank, LSA, Luhn, Edmundson, KL and related Sumy methods.

## Pipeline

Video → FFmpeg audio extraction → optional noise reduction → transcript → text preprocessing and topic tagging → extractive summary.

The recognition stage uses an external speech service. Dataset videos and transcripts are not bundled. Configure the updated dependencies in an isolated environment if reproducing the study; no environment was installed during maintenance.

## Entry points

Run commands from the repository root. `requirements.in` lists direct dependencies and `requirements.txt` locks their graph; FFmpeg and the native `deep-filter` executable are external prerequisites for their respective options. The evaluation helper also needs the `rouge` package.

```sh
python3 summarize_video.py -l vi -video data/input.mp4 -noise deep -summary lexrank -sentence 2
```

`experiments/legacy_pipeline.py` is an earlier pipeline variant. `summary/summarizers.py` contains summarizers, while `handle/` contains text and result utilities. Translation uses a synchronous facade over the current async googletrans API. Punctuation restoration is optional: set an HTTPS `PUNCTUATOR_URL` explicitly; otherwise the transcript punctuation is preserved.

## Evaluation

The original pipeline's ROUGE values measure **overlap with the source transcript**. They must not be presented as ROUGE against human-written reference summaries. The original tables are preserved with this explanation in [historical results](docs/historical-results.md).

For an independent reference, the helper accepts separate reference and hypothesis files:

```sh
python3 accuracy.py --reference data/human-summary.txt --summary data/generated-summary.txt
```

No metrics were recomputed during the 2026 repository cleanup. See [third-party notices](THIRD_PARTY_NOTICES.md) for the source generator and libraries.


## Dependency maintenance (2026-10-28)

Python dependency files are in the repository root. The main lock targets **CPython 3.12 on Linux x86_64**. `requirements.in` contains direct dependencies; `requirements.txt` is generated by the command in its header. Run the command from that same directory. Resolve again before using another Python version or platform. No machine-wide pip freeze or obsolete Conda export is used.

The optional `deep` noise mode uses the [native Rust DeepFilterNet CLI](https://github.com/Rikorose/DeepFilterNet#deep-filter), independently of Python/Torch packages. Put a trusted `deep-filter` binary on PATH or set `DEEP_FILTER_BIN` to its absolute path; set `DEEP_FILTER_MODEL` for a specific trusted model. The adapter resamples input to 48 kHz with FFmpeg and preserves existing output filenames. Those legacy suffixes do not prove which model was used. The external binary and models were not downloaded, executed or audited in this maintenance pass.

Sumy 0.13.0 is preserved with a local packaging adjustment in [`vendor/sumy/`](vendor/sumy/README.md): its unchanged library source no longer pulls an unused vulnerable setuptools runtime. The upstream license is included. Audit this vendored version as well as registry packages during future updates.

Lockfile advisory checks, source parsing and lightweight regression tests were performed during maintenance. **No application dependency environment was installed, and no full frontend build, database integration, model inference or training was run.** These archived prototypes still need runtime/integration verification before deployment.
